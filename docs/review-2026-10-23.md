# Review, 2026-10-23

## Changes

- Serialize repository mutations with a mutex and write indexes with AtomicFile before publishing state. Corrupt indexes are preserved and an error is shown instead of replacing the library with an empty index.
- Updates transform the latest document, preventing concurrent tags/page edits from losing each other. New-document navigation waits for persistence.
- Delete unreferenced originals, edited images and imported documents after saving the index, including images stored under inbox/temporary import directories. Shared files are retained.
- Store portable paths; resolve legacy absolute paths after restore. Include scans in backup/device transfer and exclude old generated exports. New exports use cache storage.
- Remove the camera-permission gate and its unused screen/strings/helper. ML Kit owns the camera flow and does not require app camera permission: https://developers.google.com/ml-kit/vision/doc-scanner.
- Crop handles align with the fitted original image; callbacks use current state and ordered bounds. Processed preview and viewer thumbnails reflect filters and rotation. Manual movement invalidates pending automatic detection. Filter controls scroll on narrow screens.
- Respect EXIF orientation, bound bitmap previews/PDF imports, correct black-and-white luminance and handle crop coordinates on the final pixel safely.
- Imports reject unavailable streams; exports report errors, release the busy state, reject missing pages and isolate each share in a unique directory. Close OCR resources.
- Removed unused date formatter, repository directory wrapper, unreachable reorder helper, imports and scanner PDF output that was never consumed. README now matches the available page-management controls.

## Validation

- All application Kotlin sources and 10 new Android instrumentation tests compiled through a fallback local K2 compiler (2.0.21), Compose compiler and cached Android libraries. Some cached Compose dependencies differ from the declared Gradle versions; this verifies source consistency, not the production build graph.
- `git diff --check`: passed.
- Gradle build/test/lint attempted. The declared Gradle 8.9 distribution is not cached. The managed environment prevents Java from resolving services.gradle.org. The normal build and lint did not run.
- Instrumentation tests cover concurrent document insertion, concurrent tag transforms, inbox/shared file cleanup, imported-file cleanup, corrupt-index preservation, folder deletion, portable paths, EXIF rotation, edge and inverted crops. They have been compiled but NOT executed on Android.
- Follow-up (same day), with JDK 17 and Gradle 8.9: `assembleDebug testDebugUnitTest lintDebug` succeeded (lint: 0 errors, 39 warnings, mostly dependency-update and launcher-icon notices). `connectedDebugAndroidTest` passed all 10 instrumentation tests on an API 34 emulator. The debug APK launched to onboarding without crashing. (An API 37 AVD with a lock-screen PIN fails these tests because credential-encrypted storage stays locked. That comes from the environment, not the app.)

## Second pass (same day)

### Changes

- Toolchain aligned with the other Android projects: AGP 8.13, Gradle 8.13, Kotlin 2.0.21 with the Compose compiler plugin, compile/target SDK 36 (Google Play requirement), Compose BOM 2024.12.01. Edge-to-edge enabled, with system bar icons following the in-app theme. Onboarding respects insets.
- Startup: the splash screen stays up until preferences are read. Before, returning users briefly saw onboarding, and a Portuguese user's activity was created and destroyed three times on every cold start (default English applied, then Portuguese). Measured with `wm_on_create_called` events: 3 creations before, 1 after.
- Searchable PDF export: A4-width pages (595 pt, full image resolution) with ML Kit OCR text drawn beneath the opaque page image. Previously each page was as many points as the scan had pixels, with no text.
- Page reordering with arrows under each page. The viewer is now a grid: in the old `LazyRow` each thumbnail took the whole screen height and pushed its buttons (including "Extract text") off screen.
- Folder chips count the whole library. Before, they counted the filtered list, so the other folders showed 0 while one was selected.
- Page previews decode off the main thread (`rememberPageBitmap`). Home cards show a top-aligned first-page thumbnail. Deleting a page asks for confirmation. The page count uses a plural resource.
- Orphaned files older than a day are removed once after the index loads successfully.
- Export names keep accents (`ExportFiles.safeName`, shared by all exporters). AndroidX `ExifInterface` is used, and image exports release their bitmaps.
- Removed: 5 unused colours, 2 unused Kotlin colours, unused round launcher icons, a FileProvider path no code shares, `vectorDrawables` with no vector drawables, unused Espresso/JUnit/ui-test-manifest dependencies (the test runner is now declared explicitly). Added a monochrome (themed) launcher icon.

### Validation

- `assembleRelease lintDebug connectedDebugAndroidTest`: build succeeded. Lint: 0 errors, 20 warnings (only newer-version notices and legacy icon shape). 14/14 instrumentation tests passed on an API 36 emulator.
- The exported test PDF was pulled from the emulator. `pdfinfo` shows an A4 page and `pdftotext` extracts the page text, positioned over the scanned text.
- Driven on the API 36 emulator with seeded documents: home, folder counts, viewer grid, reorder (persisted order checked in the index), editor, delete confirmation, light theme in Portuguese.
